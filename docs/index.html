EPSE Documentation

Efficient Protein Search Engine for resource-constrained systems, powered by modern E-Means clustering and ESM-2 embeddings on CPU.

Introduction

EPSE addresses the memory scaling bottleneck inherent in large-scale protein similarity search. Traditional vector indexing requires loading millions of high-dimensional embeddings into RAM. EPSE solves this by clustering protein embeddings using e-means and storing them in an on-disk binary format.

Core Concept: At query time, EPSE evaluates centroids first, then selectively loads only the top-scoring clusters from disk into RAM. This prunes 80% to 99% of candidate search space and RAM consumption while maintaining high retrieval sensitivity.

System Architecture

The EPSE pipeline is organized into five components:

  1. Universal FASTA Streamer (epse.fasta): Ingests sequences and metadata from any protein repository (UniProt, NCBI RefSeq, Ensembl, PDB, custom FASTA, or gzipped streams).
  2. CPU Embedding Engine (epse.embedder): Uses ESM-2 (t12, 35M parameters, 480 dimensions) on standard CPU hardware with batched inference and residue mean pooling.
  3. E-Means Clustering (epse.emeans): Meta FAIR's modern replacement for Lloyd's k-means. Combines mini-batch updates with Exponential Moving Averages (EMA), automatic scaling laws, and cosine decay.
  4. Disk-Backed Index (epse.storage): Fixed-record binary embedding files (embeddings.bin) supporting O(1) random disk access and inverted cluster indexes.
  5. Two-Stage Search Engine (epse.search): Cosine centroid ranking followed by selective disk read of candidates and fine-grained ranking.

Installation

EPSE requires Python 3.8+ and standard CPU hardware. No GPUs, CUDA drivers, or specialized accelerators are required.

# Clone the repository
git clone https://github.com/sirohikartik/EPSE.git
cd EPSE

# Create and activate virtual environment
python3 -m venv venv
source venv/bin/activate

# Install requirements and package in editable mode
pip install -r requirements.txt
pip install -e .

Command-Line Interface (CLI)

The epse command provides sub-commands for the complete workflow:

1. epse index

Indexes a FASTA file using CPU ESM-2 embeddings and E-Means clustering.

epse index <fasta_path> [options]

Options:
  --data-dir, -d   Output directory for index artifacts (default: .data)
  --k, -k          Number of clusters (default: automatic sqrt scaling)
  --epochs, -e     E-Means training epochs (default: 5)
  --batch-size, -b Inference batch size for CPU embeddings (default: 8)
  --threads        PyTorch CPU thread count (default: auto)
  --seed           Random seed for clustering initialization (default: 1234)

2. epse search

Queries a protein sequence string or FASTA file against an index.

# Query sequence string
epse search "MKTVRQERLKSIVRILERSKEPV" --data-dir .data --top-k 5 --top-clusters 3

# Query FASTA file with JSON output
epse search query.fasta --data-dir .data --format json

3. epse info

Displays cluster distribution statistics, protein count, and storage sizes.

epse info --data-dir .data

Search Workflow & Metrics

When executing a query, EPSE provides real-time performance metrics:

Metric Description Typical Value
Embedding Time Generating 480-dimensional ESM-2 embedding on CPU 50 - 150 ms
Centroid Ranking Dot-product scoring against cluster centroids < 1 ms
Disk Selective Read Direct O(1) random disk seeks for chosen clusters 0.2 - 2 ms
Candidate Ranking Cosine similarity scoring within loaded candidates < 0.5 ms
Search Space Pruning Percentage of dataset not loaded into RAM 85% - 99%

Universal Database Support

EPSE automatically parses protein records from the following formats:

  • UniProtKB (Swiss-Prot / TrEMBL): >sp|P12345|NAME_SPECIES Description OS=Organism OX=...
  • NCBI RefSeq & GenBank: >gi|12345|ref|NP_001234.1| Description [Organism]
  • Ensembl: >ENSP00000369497 pep chromosome:... description:Description [Organism]
  • PDB: >pdb|4HHB|A Hemoglobin subunit alpha OS=Homo sapiens
  • Generic FASTA: >custom_identifier Optional description tokens

Python API Reference

from epse import parse_fasta, ProteinEmbedder, EMeansClustering, IndexStorage, ProteinSearchEngine

# 1. Parse database
entries = list(parse_fasta("uniprot_sprot.fasta"))

# 2. Embed on CPU
embedder = ProteinEmbedder(normalize=True)
embeddings = embedder.embed_sequences([e.seq for e in entries])

# 3. Cluster with E-Means
emeans = EMeansClustering(k=100, nepochs=5, spherical=True)
emeans.fit(embeddings)

# 4. Save index to disk
storage = IndexStorage(".data/my_index", embedding_dim=embeddings.shape[1])
storage.save_index(
    metadata_list=[e.to_dict() for e in entries],
    embeddings=embeddings,
    cluster_assignments=emeans.labels_,
    centroids=emeans.centroids_,
)

# 5. Search
search_engine = ProteinSearchEngine(".data/my_index", embedder=embedder)
hits, metrics = search_engine.search("MALWMRLLPLLALLALWGPDPAAA", top_k=5, top_clusters=2)
for h in hits:
    print(f"Rank {h.rank}: {h.accession} ({h.organism}) - Score: {h.score:.4f}")

On-Disk File Formats

  • proteins.csv: Metadata table storing id, accession, entry_name, description, organism, seq_len.
  • embeddings.bin: Binary record file. Each entry has 4 bytes (uint32 id) followed by 480 * 4 bytes (float32 coordinates).
  • assignments.bin: 8-byte pairs storing uint32 protein_id and uint32 cluster_id.
  • centroids.csv: Centroid vectors and cluster sizes in CSV format.
  • cluster_index.json: Inverted index mapping each cluster ID to its associated protein IDs.
